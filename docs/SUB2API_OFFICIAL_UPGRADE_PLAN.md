## 正式切换与回滚操作

1. 演练、恢复、所有既有表比对、旧版兼容和本地备份校验全部成功后，才允许生产维护。
2. 先启动独立 systemd 看门狗。Nginx 临时阻断非回环请求，由本地公网确认 503，并确认服务器回环 TLS 检查为 200；排空在途请求和任务；确认无支付/批量任务在执行，再停止旧应用。
3. 确认旧应用连接退出、没有其他业务写入者；创建最终备份及冻结基线，复制到本地并核验。
4. 单独执行固定源码的迁移工具，比较全部既有表及序列；不允许绕过或修改历史 migration checksum。
5. 原子替换程序；配置、秘密、systemd unit/override 和监听地址保持原值。外部入口继续关闭，启动新版并完成认证、数据读取和静态页面验收。
6. 使用已授权的现有有效 Key 发起一次最小文本请求，确认响应与用量/计费入库。允许该请求及正常后台任务产生的明确业务变化，禁止无法解释的凭据、余额或业务记录变化。
7. 验收通过后恢复原 Nginx 配置，开放服务并取消看门狗；观察至少 30 分钟。

主要回滚路径为保留当前数据库、Redis 和文件数据，原子恢复本次保存的线上旧二进制。旧版必须已在迁移后副本上通过完整运行验证。开放后的手动回滚先阻断外部入口并排空请求，无法排空则取消回滚并保持当前服务；恢复旧服务、认证及数据读取后，恢复原 Nginx 配置。

**一旦真实调用、计费、账户令牌刷新或其他有效业务写入发生，禁止用升级前数据库/Redis 备份覆盖当前数据。** 仅在明确没有需保留的新写入时，才可按已演练流程做完整数据恢复。自动看门狗只执行保留当前数据的二进制回滚。

本次二进制回滚命令（保留当前数据）：
